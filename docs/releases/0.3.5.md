# KPress 0.3.5

Fixes a regression in `0.3.4`. Nothing else changes.

## The Wide Band’s Inset Ignored Documents Without a TOC

`0.3.4` rewrote the wide band’s column inset as `--kpress-column-inset` and gated it on
the rail conditions.
Those select the two-column grid, which needs a rail; the inset does not, because it
applies to a single column too.
So a wide document with no TOC and no reserved rail kept the single-column band’s 4rem
where `0.3.3` gave it 2.5rem.

The reading measure was never wrong — the caps derive from the inset, so the text landed
at the measure either way.
What moved was the content card’s inner padding, which an embedding host notices when it
sizes its own panels to the documented wide track (`measure + 2 × 2.5rem`) to line them
up with the document.

The inset is unconditional again, as in `0.3.3`. If you always render a TOC or reserve
the rail, nothing changes for you.

## Verification

The usual gates and the 3.12–3.14 matrix run before publication.
Every `0.3.4` reading-measure probe reserved a rail, so the un-railed path was never
rendered; the tests now render both and assert the inset matches across them.
Both new assertions fail against the `0.3.4` rule.
