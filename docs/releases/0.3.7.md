# KPress 0.3.7

Fixes to the table of contents and to reader-pane reloads, found while auditing an
embedding host, one border and one radius for all code, and the shipped mono face for
every code run.

## Table of Contents

- The active-section highlight no longer needs `IntersectionObserver`. Some webviews and
  DOM-compatible embedding runtimes do not provide it, and there the TOC highlighted no
  section as the reader scrolled.
  Without it, the TOC now follows the same reading line, a quarter of the way down the
  viewport, from a passive scroll listener that does its work once per animation frame.
  A heading with no layout box, such as one inside a closed `<details>`, is skipped, so
  it never becomes the active section.
- A TOC link that an embedding host has rewritten from a fragment to a URL keeps its
  active-section behavior when the URL still names the current document: same origin,
  path, and query. A link to another document is left out of tracking, and a link whose
  fragment cannot be decoded no longer stops the TOC’s setup.
- Wrapped TOC labels align under their first line at every depth.
  The hanging indent is gone, and the per-level insets start at `0.75rem` and step by
  `0.7rem`. The insets and the active marker use logical properties, so they sit on the
  inline-start side in right-to-left documents.

## Reader-Pane Reload

Reloading a reader pane on a URL with a fragment could land on the fragment’s target
instead of the saved position.
KPress restored the position on the first frame after `pageshow`, and WebKit can finish
its fragment landing after that frame.
The restore is now confirmed once on the next frame.
That second write is skipped if the history entry’s state was replaced in between, and
there is no third, so later scrolling stays the reader’s.

## Code and Blockquotes

- Inline and block code share one border and one radius: `--kpress-code-border`, a solid
  edge at 55% of `--kpress-doc-border`, and `--kpress-code-radius`, square by default.
  Inline code was rounded before; set `--kpress-code-radius` to round both.
- Inline code padding is `0.1em 0.25em`, so a line that carries several identifiers
  still reads as prose.
- A blockquote has a `3px` rule on its inline-start edge and muted text.
  Before, only its indentation set it apart.
- `<kbd>` and `<samp>` draw in the shipped mono face at the code size.
  They used the browser’s own monospace, beside code set in Planetaire Mono.
- Code, `<kbd>`, and `<samp>` inside a link’s preview popover draw in the shipped mono
  face too. The popover sits outside the document wrapper, so the document’s code rule
  never reached it.

## For Host Integrators

- The public contract adds `--kpress-code-border` and `--kpress-code-radius`, for pages
  and fragments. Nothing was removed.
- A host that restyled the TOC insets, the code edge, or blockquotes itself can compare
  its overrides with these defaults and drop the ones that now match.

## Verification

The usual gates and the 3.12–3.14 matrix run before publication.
Browserless tests drive the shipped `toc.js` without `IntersectionObserver` and with
rewritten and malformed links, and the shipped `history.js` through a fragment landing
that arrives a frame late.
The real-browser reload cases run in Chromium, Firefox, and WebKit.
