# KPress 0.3.9

Mermaid diagrams drawn as GitHub draws them, by a renderer a host can configure, with
visible errors and opt-in controls.

KPress still does not ship Mermaid: a page or host supplies it.
The
[host-integration guide](../kpress-operations-and-host-integration.md#mermaid-diagrams)
has the full API.

## Diagram Modes

- `diagrams: mermaid` draws Mermaid only and leaves `svg` fences as highlighted code, as
  GitHub does. The mode existed but behaved like `auto`.
- A dynamic render selects the mode too: `KPressRenderRequest.diagrams` takes `"auto"`
  (the default), `"mermaid"`, or `"off"`, and any other value fails with
  `KPressInvalidRequestError`.

## A Host-Configured Renderer

- `initKpressDiagrams(root, options)` in `js/diagrams.js` takes the Mermaid API, an ES
  module namespace, or a loader, so a host never has to set `globalThis.mermaid`. The
  loader is called once, and only when the page holds a diagram.
  The same options go to `kpress.behaviors.configure("diagrams", options)`.
- A host’s `config` is merged over GitHub’s settings with `securityLevel: "strict"`, and
  `theme` and `subscribeTheme` let the host say which theme to draw in and when it
  changes. Without them, a diagram follows the KPress theme and redraws when it changes.
- `placement: "image"` shows each drawing as an `<img>` from a `data:` SVG URL, for
  content the host does not trust.
  It keeps a label to formatting tags, and it works under a Content-Security-Policy that
  admits no `<style>` element.
- **`initKpressDiagrams` now returns a binding instead of a promise.** Awaiting the
  drawing is `await initKpressDiagrams(root).ready`; the binding also has `rerender()`
  and `dispose()`. It was not a pinned export before this release.

## Errors

- A diagram that fails shows Mermaid’s message in a note above its source, which stays
  visible. Before, the source was left as it was with no explanation.
- A source longer than `MAX_DIAGRAM_TEXT`, Mermaid’s own limit, gets a message instead
  of a render.

## Controls

`js/diagram-controls.js` is opt-in and registers nothing at import.
`diagramControls(options)` gives each figure a toolbar to copy the source, show it, and
expand the drawing into a dialog that zooms and pans by button, wheel, pinch, drag, and
key. A host can supply its own icons, decorate the buttons, take over or omit copy, and
omit expand.

A host that sanitizes the render loses the inline icon sprites; the controls fetch each
missing one from beside the module, once per document.

## Contract and Page Weight

- `PUBLIC_JS_EXPORTS` pins the exports of both diagram modules, and `PUBLIC_CSS_CLASSES`
  gains the `kpress-diagram-*` classes.
  `PUBLIC_DIAGRAM_SCRIPT_MODULES` and `PUBLIC_DIAGRAM_SPRITES` in `contract.py` name
  what a page with diagram controls loads, for a host whose policy admits exact URLs.
- A page without a Mermaid figure loads nothing new.
  `components.css` grows by about 0.7 KB gzipped on every page, for the toolbar, error
  note, and dialog rules.
- Runtime dependencies are unchanged.
