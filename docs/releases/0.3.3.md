# KPress 0.3.3

KPress `0.3.3` is a compatible maintenance release for the `0.3` declarative-embedding
line.
It changes when an automatic table of contents is rendered, and gives dynamic hosts
the TOC controls the static publish path already had.

The public API grows but does not break: `TocMode` was already exported, and the three
new `KPressRenderRequest` fields carry defaults that describe the new behavior.
The one observable change is which documents earn a TOC, described below.

## A TOC Now Takes Both a Heading Count and a Length

A table of contents is navigation, and navigation only earns its space on a document a
reader cannot take in by scrolling.
`include_toc="auto"` tested only `len(tree.toc) >= toc_min_headings`, so a half-screen
note with four short sections got the same sidebar as a long reference document — every
one of its sections already on screen, with a list of them beside it.

Length alone would be no better: a long unbroken essay with three headings gets a TOC
that cannot help either.
`"auto"` now requires both thresholds.

| Option | 0.3.2 | 0.3.3 |
| --- | --- | --- |
| `toc_min_headings` | 4 | 7 |
| `toc_min_words` | — | 800 |

800 words is between one and two printed pages.
Together the two ask the question that actually matters: is this long enough to scroll
past, and divided finely enough that scrolling is a poor way to reach a part of it?

Length is `DocumentTree.word_count`, counted on the **rendered HTML’s visible text**
rather than the Markdown source, so table cells and list items count while link targets,
attributes, and fence syntax do not.
Counting the source would let nine one-line sections full of long URLs clear a word
threshold they have no reading length to justify.

`include_toc="on"` and `"off"` bypass both thresholds, as before.

### What Changes for You

Documents between the old and new bars lose their TOC. That is the intent of the
release, but it is a rendering change rather than a fix, so it is worth a look at any
short-but-sectioned page you publish.
Nothing else about those documents changes; the reading column keeps its position and
measure when `toc_rail` is `reserved`.

A host that wants the previous behavior restores it exactly, with no fork and no host
CSS:

```yaml
format:
  toc_min_headings: 4
  toc_min_words: 0
```

The same two fields exist on `RenderOptions` and `KPressRenderRequest`.

## Dynamic Hosts Can Switch the TOC Off

`KPressRenderRequest` could collapse a TOC and reserve its rail but could not switch it
off, so an embedding host had no way to render one document without one.
That is the common case for a host that embeds a document inside its own navigation — a
README shown in a folder summary, a description beside a list — where the surrounding
chrome is the navigation and a second one inside the embed competes with it.

`include_toc`, `toc_min_headings`, and `toc_min_words` join `KPressRenderRequest` and
`PUBLIC_RENDER_REQUEST_FIELDS`:

```python
KPressRenderRequest(..., include_toc="off")
```

Suppressing the TOC beats hiding it with host CSS, which builds the layout and then
covers it up.

All three are validated at the request boundary as a closed choice and as integers ≥ 0,
with `bool` rejected explicitly because `bool` is an `int` in Python.
All three also join the render cache identity, so two hosts rendering one document under
different TOC settings cannot share a cache entry.

## Compatibility

No name, CSS class, CSS variable, template variable, or data attribute was removed or
renamed. `RenderOptions.toc_min_headings` changes its default and
`RenderOptions.toc_min_words` is new; `DocumentTree` gains `word_count`, defaulting to
`0` for trees built outside the Markdown parser.
`format.toc_min_words` joins the static dialect.

The accepted goldens that carry a TOC re-render unchanged, so the documents that lose
one are the short ones.

## Dependency Hygiene

The development lockfile pins `nanoid@3.3.18`, clearing GHSA-2v37-7h3g-55p8. The
advisory covers a denial of service reachable only through a custom generator asked for
size zero; `nanoid` reaches this repository solely as a development dependency (`vitest`
→ `vite` → `postcss`), and `postcss` calls `nanoid(6)` with a fixed nonzero size.
No shipped artifact is affected.
The adoption is recorded under [Granted Exceptions](../../SUPPLY-CHAIN-SECURITY.md)
because the fix was 8 days old against the repository’s 14-day cool-off.

## Verification

The complete Python and JavaScript quality gates, locked-graph dependency audits,
distribution inspection, clean-room wheel install, and the Python 3.12–3.14 CI matrix
run before publication.

The threshold change is behavioral rather than geometric, so it is pinned by unit tests
rather than by a browser probe: each threshold is exercised in isolation, with fixtures
that sit on the far side of one and the near side of the other so neither can pass by
clearing the test it was not meant to clear.
The visible-text measurement has its own test built from link-heavy one-line sections.
The dynamic path is covered for suppression, cache identity, and every out-of-contract
value. The real-browser TOC and history suites still pass, with their fixtures grown to
clear the new bar.

The exact PyPI artifact is verified separately after trusted publication.
