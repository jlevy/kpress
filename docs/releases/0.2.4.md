# KPress 0.2.4

KPress `0.2.4` is an alpha release that deliberately improves public identifier design
before the package stabilizes.
It adopts pinned GitHub-compatible heading anchors, decouples footnote and table
metadata from heading slugs, ships the merged presentation and collapsible-TOC work, and
hardens the release gates.

## Required Anchor Migration

[GitHub issue #33](https://github.com/jlevy/kpress/issues/33) identified that KPress’s
ASCII-only heading ids did not match GitHub links.
KPress now uses a dependency-free Python implementation pinned to `github-slugger` 2.0.0
at commit `3461c4350868329c8530904d170358bca1d31448`, its Unicode 13 exclusion data, and
the complete published 78-case fixture sequence.

Representative changes:

| Heading | Before 0.2.4 | 0.2.4 |
| --- | --- | --- |
| `Figma's Share Price` | `#figma-s-share-price` | `#figmas-share-price` |
| `S&P 500` | `#s-p-500` | `#sp-500` |
| `Café Notes` | `#caf-notes` | `#café-notes` |
| second `Summary` | `#summary-2` | `#summary-1` |
| `<em>Raw HTML</em>` | `#em-raw-html-em` | `#raw-html` |
| `!!!` | `#section` | an empty id, matching the pinned upstream contract |

Visible plain heading text is the slug input.
Unicode is preserved according to the pinned contract, literal ASCII spaces become
hyphens without trimming or collapsing, and collisions use GitHub’s suffix bookkeeping
from `-1`. Heading markup, document metadata, TOC links, the page model, browser
behaviors, and internal-link diagnostics all use the same generated id.

Downstream users must regenerate stored deep links, search or link indexes, cached HTML,
and any host-authored fragment URLs when upgrading.
KPress emits no legacy anchors, alias ids, redirects, dual TOC targets, or compatibility
mode.

## Footnote and Table Identifier Migration

- Footnote DOM and model ids now use document-order ordinals: `fn-1`, `fnref-1`, and
  `fnref-1-2` for a repeated reference.
  Authored labels remain parser input and diagnostic context only.
- `data-col` now contains the whitespace-normalized visible header label with case,
  punctuation, and Unicode preserved.
  Header-backed cells also carry the 1-based `data-col-index`, which disambiguates
  duplicate and empty labels.
  The former kebab-case column value is not emitted under another attribute.

Hosts that select footnotes by authored label or table columns by the former ASCII slug
must migrate to ordinal footnote ids and literal label/positional table metadata.

## Presentation and Reader Behavior

- The collapsible TOC can keep deep entries compact, expand the active section through
  scroll-follow, and expose an expand-all control.
  Runtime-only configuration now creates equivalent accessible chrome when the server
  rendered collapse off, and disposal restores markup and ARIA state cleanly.
- The opt-in document-actions widget provides export and Markdown-view actions in the
  document card.
- Responsive heading, table, footnote, TOC, print, and content-card presentation
  refinements from the post-0.2.3 work are included.

## Release Quality and Security

- Dynamic rendering rejects boolean, floating-point, string, zero, and negative TOC
  collapse depths with `KPressInvalidRequestError`.
- Tooltip Playwright smokes use system Chrome when managed Chromium is unavailable and
  fail rather than skip in CI when no real browser exists.
- The npm graph pins the oldest policy-compliant patched PostCSS release and passes the
  locked dependency audit.
- Browser coverage exercises Unicode TOC navigation, encoded history fragments,
  duplicate headings, scroll-spy lookup, and internal-link tooltips.

## Compatibility

This is an intentional alpha breaking release.
No backward-compatibility shims are provided for heading, footnote, or table
identifiers. The typed Python API remains the supported integration surface, while
rendered output and host selectors must follow the new contracts described above.

## Verification

The complete Python and JavaScript quality gates, dependency audits, distribution
inspection, clean-room install, CLI and bundled-example smokes, real-browser reader
checks, and exact Python 3.12–3.14 CI matrix run before publication.
The exact PyPI artifact is verified separately after trusted publication.
