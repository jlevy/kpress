# KPress 0.3.1

KPress `0.3.1` is a compatible maintenance release for the `0.3` declarative-embedding
line.
It adds an opt-in reserved TOC rail so a host that shows one document after another
can keep the reading column in one place, and it carries the development-only dependency
patches the release audit requires.

Nothing in this release changes default output.
A `0.3.0` host that upgrades and changes no configuration renders byte-identical HTML,
CSS class names, and data attributes.

## Reserved TOC Rail

In the wide band (≥ 75rem of *pane* width) the TOC is a sticky left sidebar and the
reading column is grid track 2: a constant 48rem of text at a constant distance from the
pane’s left edge. A document that falls under `format.toc_min_headings` earns no TOC, so
it also left the grid and reverted to the centred, measure-capped single column.
That fallback moved the prose sideways **and** narrowed it — the 2.5rem inset on
`.kpress-content-with-toc .kpress-long-text` is sized for the 53rem grid track, so
against the 48rem cap it cost 5rem of measure.
Across a set of documents with varying heading counts the column visibly jumped.

The new `toc_rail` option chooses which behavior a surface wants:

- `auto` — the default and the historical behavior.
  The rail exists only when a TOC does.
- `reserved` — the rail is a fixed part of the layout whenever TOCs are enabled at all
  (`format.toc != "off"`), so the reading column keeps one position and one measure with
  or without the sidebar.
  The TOC itself is still omitted on short documents; only the empty track remains.

Reserving suits surfaces that show one document after another — a file browser, a
multi-page site. A lone standalone document usually wants `auto`.

| Surface | Setting |
| --- | --- |
| Static publish | `format.toc_rail: reserved` in `kpress.yml` |
| Python render | `RenderOptions(toc_rail="reserved")` |
| Dynamic host | `KPressRenderRequest(toc_rail="reserved")` |

The dynamic path membership-checks the value at the request boundary, so a typo raises
`KPressInvalidRequestError` rather than silently rendering the other layout.
The option has no effect below the 75rem band, where no rail exists to reserve, or when
`format.toc` is `off`.

Mechanically, the renderer stamps `data-kpress-toc-rail="reserved"` on the layout
wrapper in the held-open-but-empty case only; a rendered TOC needs no stamp because the
CSS already keys off the nav.
Every wide-band rule that keys off the TOC therefore selects on three conditions —
`.has-toc`, `:has(.kpress-toc)`, and `[data-kpress-toc-rail="reserved"]`. The layout
comment at the top of `components.css` is the binding reference for anyone adding a rule
to that band. The optional thumbnail is now pinned to the reading column, so grid
auto-placement can no longer drop it into the reserved-but-empty rail.

## Public Surface

The change is purely additive.
`TocRail` joins `PUBLIC_FORMAT_API`, `toc_rail` joins `PUBLIC_RENDER_REQUEST_FIELDS`,
and `format.toc_rail` joins the static configuration dialect.
No name, CSS class, CSS variable, template variable, or data attribute was removed or
renamed, and no compatibility shim was added.

Full contract: [Reserved TOC Rail](../kpress-design.md#reserved-toc-rail).
Host integration:
[Reserved TOC Rail](../kpress-operations-and-host-integration.md#reserved-toc-rail).

## Dependency and Release Hygiene

- PostCSS moves to 8.5.23, past GHSA-fxqj-rqcc-2cmp, an arbitrary `.map` read from an
  attacker-controlled `sourceMappingURL` when `from` is unset.
  PostCSS is a development-only transitive dependency through Vitest and Vite, so no
  published artifact was affected, but the locked-graph audit is a release gate.
- Nano ID moves to 3.3.17, past GHSA-2v37-7h3g-55p8 / CVE-2026-67213, an infinite loop
  in `customAlphabet` and `customRandom` when either is called with a size of zero.
  Nano ID is a development-only transitive dependency through Vitest, Vite, and PostCSS,
  and the only call site in the installed tree is PostCSS’s own `nanoid(6)` with a
  hardcoded size, so neither the vulnerable functions nor any published artifact was
  reachable — but the locked-graph audit is a release gate.
- Nano ID 3.3.17 is a **documented cool-off exception**: every patched version was still
  inside the repository’s 14-day supply-chain window at release time.
  It is pinned exactly, its registry integrity hash was verified against the downloaded
  tarball, its npm provenance attestation resolves to a workflow build from
  `github.com/ai/nanoid` at tag `3.3.17`, and its published code matches that git source
  with no differences outside stripped comments.
  The 3.3.16 to 3.3.17 diff is the advisory’s zero-size guard and the version bump and
  nothing else. See [`SUPPLY-CHAIN-SECURITY.md`](../../SUPPLY-CHAIN-SECURITY.md) for the
  exception process.
- Every other dependency move in this release cleared the 14-day cool-off at resolution
  time under the checked-in `.npmrc` policy rather than any ambient configuration.

## Compatibility

No migration is required.
`toc_rail` defaults to `auto`, which reproduces `0.3.0` rendering exactly; adopting
`reserved` is a deliberate per-surface opt-in.

## Verification

The complete Python and JavaScript quality gates, locked-graph dependency audits,
distribution inspection, clean-room wheel install, and the Python 3.12–3.14 CI matrix
run before publication.
Real-Chromium regressions assert the geometry claim directly: with `reserved`, a
TOC-bearing and a TOC-less document put the reader’s text at the same left edge and the
same measure; with `auto`, the historical centred fallback is unchanged; and the
thumbnail stays out of the empty rail.
Container queries and `cqw`-keyed table caps are not evaluated by browserless DOM
emulation, so those claims are only meaningful in a real engine.
The exact PyPI artifact is verified separately after trusted publication.
