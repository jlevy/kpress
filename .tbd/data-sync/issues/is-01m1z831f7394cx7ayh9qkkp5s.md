Owner (2026-09-08): Planetaire is a good default, but every part of it must be adjustable through standard kpress settings, and Planetaire's other weights (Medium, SemiBold, ExtraBold and the italics) must not load unless enabled, since a single-file page inlines every face it declares. Follow the math_text_font pattern and put all three on one surface (RenderOptions field, format.* config key, a data attribute stamped by the render, a CSS switch, the public names pinned in kpress.contract, one settings table in kpress-design.md that lists every font setting with its option, key, attribute and host hook): (1) mono_font: planetaire (default) or system; system makes --kpress-font-mono the system stack (ui-monospace, SFMono-Regular, Menlo, Consolas, monospace) and leaves the Planetaire faces undeclared, so nothing is fetched or inlined. (2) mono_weights: which Planetaire styles are declared; default regular and bold (400, 700); italic, bold italic, medium 500, semibold 600 and extrabold 800 opt in by name; only declared faces exist in the stylesheet, so a hosted page fetches only what its code uses and an inlined page carries only what was enabled; vendor the latin subsets of the styles kpress offers, generated by a tool with --check and recorded in the fonts README. (3) The size ratio: --kpress-font-size-mono (0.87 of the prose size by the owner's decision, with small and tiny in proportion) behind a --kpress-host-font-size-mono hook so a host can retune it without forking the token. Docs: kpress-design.md (the settings table and the Mono Face section), the operations doc (what a host that inlines assets prunes when mono_font is system), tests and goldens in the same commit, no shims.

## Notes

Implemented in PR #62 (commit 4f6aa4b), on the math_text_font pattern: RenderOptions.mono_font and .mono_weights, format.mono_font and format.mono_weights, data-kpress-mono-font stamped on <html> by the page shell, a CSS switch in style-tokens.css, MonoFont / MonoWeight pinned in kpress.contract and exported from kpress.format, one settings table in kpress-design.md listing every font setting with its option, key, attribute and host hook, and the ops doc saying what an inlining host prunes.

Only declared faces exist in the page, and the mechanism is one stylesheet per style: devtools/subset_mono.py writes css/mono-planetaire-<weight>-<style>.css beside each subset and the render selects among them, so nothing rewrites CSS at render time. mono_font="system" therefore leaves both the stylesheets and the woff2 out of the manifest entirely (nothing linked, copied, fetched or inlined), which is why it is a render option rather than only a CSS switch; font_mode="system" now also covers mono, as a display switch that leaves the asset set alone the way it does for PT Serif. The size ratio is --kpress-font-size-mono behind --kpress-host-font-size-mono, with the small and tiny rungs derived from the mono rung so one hook retunes all three.

One finding worth the owner's attention. syntax.css sets comments and docstrings italic, and the default pair (regular, bold) declares no italic, so a browser synthesizes the slant rather than drawing it. The owner's stated default is kept and the trade is now documented in kpress-design.md, the fonts README and the ops doc (about 15 KB per drawn style; wrong to pay on a prose page with one code comment, right on a page of annotated code), with a test that fails if either half moves. A site with heavily commented code should set mono_weights: [regular, bold, italic, bold-italic].
